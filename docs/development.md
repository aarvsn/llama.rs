# Development

## Setup

```sh
git clone https://github.com/aarvsn/llama.rs
cd llama.rs
cargo build            # debug build
cargo test --workspace # full test suite
cargo fmt              # formatting (CI checks it)
cargo clippy --all-targets --all-features -- -D warnings
```

Stable Rust 1.85+ (edition 2024). `rust-toolchain.toml` pins the stable
channel with rustfmt and clippy.

## Layout

See docs/architecture.md. Quick orientation:

- Quantization math: `crates/llama-kernels/src/quant.rs` + `vecdot.rs`
- SIMD: `crates/llama-kernels/src/simd.rs` (runtime-detected)
- Transformer: `crates/llama-model/src/llama.rs`
- Generation loop: `crates/llama-runtime/src/session.rs`
- Tokenizers: `crates/llama-tokenizer/src/{spm,bpe,pre}.rs`
- Test fixtures: `crates/llama-fixtures`

## Testing strategy

Three layers, all runnable offline:

1. **Unit tests** in each crate with hand-computed expectations (block
   layouts, F16 exhaustive round trip, RoPE pairs, sampling distributions,
   pre-tokenizer splits, ...).
2. **Reference-value tests** (`tests/reference_kernels.rs`): kernels are
   compared against `tests/reference_values.json`, generated by
   `scripts/generate_reference_values.py` — an independent Python
   translation of the ggml C reference. Regenerate after touching block
   layouts:
   ```sh
   python3 scripts/generate_reference_values.py > tests/reference_values.json
   ```
3. **Pipeline tests** (`tests/pipeline.rs`): synthetic GGUF models in every
   quantization scheme exercise loading, prefill, KV-cache reuse,
   generation determinism, stop conditions and statistics. The strongest
   property: *batched prefill must produce the same logits as
   token-by-token processing*.

Optional real-model tests (skipped by default):

```sh
LLAMA_RS_TEST_MODEL=/path/to/model.gguf \
  cargo test --test real_model -- --ignored
```

A tiny validated model: Karpathy's stories15M (15M params) via
`crates/llama-fixtures/examples/convert_llama2c.rs`:

```sh
# .bin + tokenizer.bin from github.com/karpathy/llama2.c
cargo run --release -p llama-fixtures --example convert_llama2c -- \
    stories15M.bin tokenizer.bin stories15M.gguf f32
```

The llama forward pass was validated **bit-exactly against llama2.c**
(logits identical to 4 decimals on fixed prompts) — keep it that way when
touching kernels or the forward pass.

## Debugging aids

- `LLAMA_RS_NO_SIMD=1` — force scalar kernels (isolate SIMD issues).
- `LLAMA_LOG=debug` — tracing verbosity (`llama-core::logging`).
- `llama run --stats` — prefill/decode throughput and memory accounting.

## Conventions

- `cargo fmt` formatting; clippy pedantic (with the workspace allow-list).
- Every `unsafe` block carries a `SAFETY` comment (there are few: mmap and
  SIMD intrinsics only).
- No placeholders in shipped code: unfinished features return explicit
  errors (see `LlamaError::Unsupported*`).
- Errors are specific and actionable; never silently ignored.
- New quantization types need: block geometry in `llama-core`, dequant +
  vec_dot in `llama-kernels`, reference values regenerated, a fixture
  scheme and documentation rows.

## Release checklist

1. `cargo test --workspace` green.
2. `cargo clippy --all-targets --all-features -- -D warnings` clean.
3. `cargo fmt --check` clean.
4. `cargo doc --no-deps` builds without warnings.
5. Release build of both binaries runs the smoke test on stories15M.
6. CHANGELOG.md updated; tag `vX.Y.Z` (the release workflow builds and
   uploads artifacts for the tag).
