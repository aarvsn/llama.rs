# Architecture

llama.rs is a Cargo workspace of focused crates. Data flows downward only:

```
            llama-cli  llama-server
                 │           │
            llama-runtime ───┘
        │        │         │
 llama-model llama-sampling │
        │                   │
 llama-tokenizer      llama-kernels
        │                   │
     llama-gguf ──► llama-tensor ──► llama-core
```

## Crates and responsibilities

### llama-core
Shared error type ([`LlamaError`]), engine options, the F16 conversion
(tested exhaustively over all 65536 bit patterns), the GGML tensor-type
enumeration with block geometry, CPU feature detection and logging setup.

### llama-gguf
A strict GGUF v2/v3 reader: magic/version validation, metadata tree
(`GgufMetadata` with typed accessors), tensor directory with alignment and
bounds validation, and memory-mapped zero-copy tensor bytes. Also contains
a GGUF v3 writer used by test fixtures and the llama2.c converter example.

### llama-tensor
`Shape` (GGML fastest-first dimension order), owned `Tensor` buffers for
activations, and `WeightMatrix` — a validated zero-copy view over
serialized weight bytes that kernels consume directly.

### llama-kernels
The compute layer:

* `quant` — block layouts and reference dequantization for every supported
  GGML type, plus the Q8_0 activation quantizer.
* `vecdot` — scalar dot products for all type pairs (integer accumulation,
  ggml-compatible).
* `simd` — AVX2/FMA/F16C kernels with runtime detection (`LLAMA_RS_NO_SIMD=1`
  forces the portable path for debugging).
* `dispatch` — picks the fastest kernel for a (weight type, activation) pair.
* `matmul` — row-parallel batched matmul over a rayon pool.
* `ops` — RMSNorm, RoPE (interleaved and half-split pairing), softmax, SiLU.

### llama-tokenizer
Vocabulary storage with piece kinds, scores, byte tokens and special-token
splitting; the SentencePiece unigram merge encoder (llama.cpp-compatible);
byte-level BPE with GPT-2/Llama-3/Qwen pre-tokenizers; incremental UTF-8
buffering detokenizer; chat-template rendering for known families.

### llama-model
Architecture detection (`general.architecture`), Llama hyper-parameter
parsing with validation, weight loading with shape checks (1-D norms are
dequantized once at load; everything else stays zero-copy), the KV cache
(f32/f16), and the batched forward pass.

### llama-runtime
`Engine` (owns model + tokenizer, immutable, cloneable), `Session` (KV
cache + scratch buffers + token accounting), prompt prefill with KV prefix
reuse, the decode loop with stop conditions, streaming callbacks, and
performance statistics.

### llama-sampling
Sampling pipeline (penalties → temperature → top-k → top-p → min-p → sample)
with a self-contained xoshiro256** RNG for cross-platform determinism.

### llama-cli / llama-server
User-facing binaries. The server keeps one session behind an async mutex
(one generation at a time, like llama.cpp without `--parallel`) and streams
tokens over SSE.

## Key design decisions

**Zero-copy weights.** GGUF tensor bytes are borrowed from the memory map
for the whole life of the engine. Nothing is dequantized into F32 wholesale;
kernels read the quantized blocks directly.

**Quantize once per row.** For each matmul, activation rows are quantized to
Q8_0 once (or copied for F32/F16 weights) and reused across every output
channel.

**Batched prefill.** Prompts are processed in batches (up to 256 tokens);
logits are computed only for the last position.

**Positions shared across layers.** The KV cache tracks one length for all
layers; sessions truncate it for prefix reuse when a new prompt extends a
previous one.

**Runtime SIMD.** Binaries target the baseline ISA; AVX2/FMA/F16C are
detected at runtime. The `LLAMA_RS_NO_SIMD=1` environment variable forces
scalar kernels (debugging aid).

**RoPE convention.** GGUF llama models use the ggml `GGML_ROPE_TYPE_NORMAL`
pairing — consecutive pairs `(x[2i], x[2i+1])` — because HF→GGUF converters
permute Q/K weights into that order. llama.rs implements exactly this
(validated bit-exactly against llama2.c on a real model), plus the NeoX
half-split style for future architectures.

**Validation strategy.** Three independent lines of evidence:
1. Unit tests with hand-computed references.
2. Kernel tests against `tests/reference_values.json`, generated by an
   independent Python translation of the ggml C reference.
3. End-to-end tests against real GGUF models (stories15M), including
   bit-exact logit comparison against llama2.c.
